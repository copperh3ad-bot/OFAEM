# Testing OFAEM

Three layers of automated checks; CI runs the fast ones on every push.

| Layer | Coverage | Latency | Runs in CI? |
|---|---|---|---|
| Unit tests (`tests/unit/`) | Pure logic: CBM resolver, confidence rollup | < 1s | ✅ |
| Lint + migration sanity | Syntax, every migration applies cleanly | ~30s | ✅ |
| Integration tests (`tests/integration/`) | Live HTTP against deployed edge functions | 1–3min | ❌ (manual / nightly) |

## Unit tests

```bash
deno test tests/unit/
```

These exercise pure shared modules without network access. Add new ones for
any non-trivial pure logic — they're the cheapest layer to keep green.

## Integration tests

All integration tests target the live project at
`https://ouxnplyjzlbhmvpcvjmx.supabase.co` (configurable via `SUPABASE_URL`).

### Required env vars

| Var | Used by |
|---|---|
| `SUPABASE_ANON_KEY` | every integration test (anon-side calls) |
| `SUPABASE_SERVICE_ROLE_KEY` | `workflow_e2e.test.ts` (Stage 2-4 role auth) |
| `INGEST_WEBHOOK_SECRET` | `classifier.test.ts` (current value: rotate before prod) |

Tests that don't see their required env vars skip cleanly with a stub
"[skipped] …" test so the suite never fails for misconfiguration.

### Suites

**`extraction.test.ts`** — fixture-driven extraction coverage.
- 7 fixtures under `tests/fixtures/pos/inputs/` (email × 3, pdf × 1, xlsx × 2, image × 1)
- Each paired with `tests/fixtures/pos/expected/<name>.expected.json` describing
  invariants (po_id substring, currency, line count bounds, total value
  within ±2-5%, etc.) — see `tests/fixtures/pos/expected/README.md`
- `tests/helpers/compare.ts` enforces the spec

```bash
SUPABASE_ANON_KEY=eyJ... \
  deno test --allow-env --allow-net --allow-read tests/integration/extraction.test.ts
```

**`classifier.test.ts`** — PO vs not-PO corpus.
- 10 positive + 10 negative emails under `tests/fixtures/emails/{po,not_po}/`
- Asserts PO confidence ≥ 0.65 and NOT_PO confidence ≤ 0.50

```bash
SUPABASE_ANON_KEY=eyJ... INGEST_WEBHOOK_SECRET=... \
  deno test --allow-env --allow-net --allow-read tests/integration/classifier.test.ts
```

**`workflow_e2e.test.ts`** — one PO walked through every stage.
- parse-po → plan-logistics → generate-schedule → record-quality
- Verifies `workflow_state.current_stage = READY_SHIPMENT` at the end

```bash
SUPABASE_ANON_KEY=eyJ... SUPABASE_SERVICE_ROLE_KEY=eyJ... \
  deno test --allow-env --allow-net tests/integration/workflow_e2e.test.ts
```

**`pipeline.test.ts`** — legacy smoke test, kept for compatibility.

## Regenerating fixtures

Inputs are generated by Python scripts so changes are auditable:

```bash
python3 tests/fixtures/generate_po_fixtures.py
python3 tests/fixtures/emails/generate_classifier_corpus.py
```

Both require `Pillow` and `openpyxl`. The PDF fixture uses macOS `cupsfilter`
(install via `brew install cups` if missing).

## Bootstrapping a fresh test project

```bash
export SUPABASE_PROJECT_REF=<your-ref>
export SUPABASE_SERVICE_ROLE_KEY=eyJ...
./scripts/seed_all.sh   # migrations + master_articles + customer_map + demo users
./scripts/seed_demo_po.sh  # one PO through all 5 stages so the UI shows data
```

Time budget: 1–2 min total. The demo PO will appear at
`current_stage = READY_SHIPMENT` in the UI dashboard.

## Cost note

Every integration run triggers real Anthropic calls. Estimated cost per
full run (extraction + classifier + workflow): ~$0.10–0.30 depending on
how many fixtures hit the Sonnet fallback. Don't loop them in tight CI;
nightly or per-release is more economical.
